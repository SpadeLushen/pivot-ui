# pi 1.4.0：Pivot 用户会感受到哪些变化

这次更新主要改善多会话并行、长对话恢复和模型可用性，并让更多分类模型能够理解图片。

**当前状态**：pi 1.4.0 适配与底部询问面板改造已完成，两阶段工作区构建通过。尚未执行浏览器或真实服务行为验收，也未重启现有服务；以下体验在加载本次构建后生效。

## 升级后，多会话同时使用 codemode 更少立即报错

codemode 是让模型通过一段脚本组合调用多个工具的能力。以前，同一个服务中的两个脚本占满执行名额后，新脚本会立即失败；1.4.0 会先按到达顺序等待空闲名额。

- 默认仍是整个服务共两个执行名额，不是每个聊天各两个，也不是所有聊天只能同时运行两个。
- 最多等待 60 秒；脚本设置了更短的超时时间时，等待也计入该时间。
- 等待超时或在等待中取消，脚本不会开始执行。
- 刚取消的脚本可能还在退出，名额不会立刻释放。

因此，繁忙时工具卡片可能先保持“进行中”，稍后才有输出。新版没有队列位置通知，不能据此判断前面还有几个任务。Pivot 已补齐新的失败提示，区分等待超时、等待中取消与脚本执行失败。

## 升级后，长对话更容易压缩并继续

**摘要不再容易被旧的固定输出上限截断**。 长推理模型生成压缩摘要或分支摘要时，会使用模型自身的输出限制。摘要可能花更长时间、消耗更多 tokens；这不等于扩大了聊天模型的上下文窗口。

**手动压缩的要求更完整地生效**。 例如发送 `/compact 重点保留部署步骤和待处理错误`，即使压缩需要截取一轮很长的工作记录，摘要也会遵循这段要求。

**部分卡在错误状态的会话可以正确恢复**。 模型输出被截断后，新版会在恢复上下文时一起处理未完成的工具调用及对应结果，减少之后每次发送都被 Provider 拒绝的问题。历史记录与已经发生的费用不会因此删除。

GitHub Copilot 因大量图片等内容导致请求过大时，新版也能识别这类错误，并按上下文溢出流程尝试压缩后重试。

## 升级后，部分网络和工具错误更容易恢复

- 更多代理断流、网关失败和临时认证网络错误能够进入正常重试流程。
- 请求编号或字节数中恰好包含某些数字，不再容易被误判成可重试的 HTTP 错误。
- ChatGPT Business 工作区额度用尽时，会明确提示联系管理员增加额度，而不是反复重试。
- 工具只返回空格或换行时，更少触发模型接口的请求格式错误。
- 支持相关能力的 OpenAI Responses 模型，在动态加载工具后更容易保留提示缓存，减少重复处理相同上下文的开销；实际收益取决于模型和 Provider。

## 更多分类模型能看图片，模型目录也有调整

### 用图片回答具体问题

分类模型适合回答“截图是否存在布局问题”“这张图片属于哪个类别”等有明确选项或评分标准的问题，不是聊天模型，也不是图片生成模型。

1.4.0 为 TypeSafe 的 Jev、Cloudflare Workers AI 的 Jev/Clef，以及目录中标注支持图片的 OpenRouter 分类模型接通图片输入。模型可通过 codemode 调用这些能力，前提是相应 Provider 已配置、模型支持图片且工具已启用。

- Jev 支持 PNG、JPEG；TypeSafe 官方图片能力仍属实验功能。
- Cloudflare Clef 支持 PNG、JPEG、WebP，每次最多四张。
- OpenRouter 以具体模型的目录能力为准，不是所有分类模型都支持图片。

Pivot 当前 Models 中的分类测试入口仍只接受文字/JSON；聊天模型收到附件也不等于自动使用分类模型。Pivot 已补齐自定义分类模型的图片兼容配置传递；使用代理时，仍需确认配置与实际服务的图片格式一致。

### 新模型、思考选项和费用信息

- MiniMax 新增 **MiniMax-M3.1-Flash**，提供 low 到 max 的思考级别，不支持关闭思考。
- xAI 的 **Grok 4.3、Grok 4.5** 增加 xhigh 思考选项。
- Cloudflare Workers AI 新增 **Clef Omni、Jev 1.14** 分类模型。
- Cloudflare Clef Flash 的目录价格修正为每百万输入 tokens **$0.038**，上下文窗口修正为 **24,576 tokens**；Jev 的输入价格修正为 **$0.042**，不再显示为免费。
- `openai-codex` 移除 ChatGPT 账户无法使用的 **gpt-5.5、gpt-5.3-codex-spark**；其他部分退役模型也从目录移除。

上游还调整了 GitHub Copilot、NVIDIA 和 Xiaomi 的启动默认模型。Pivot 不会据此自动重写你保存的默认选择；如果原模型已退役，需要自行选择替代模型。目录价格变化不会重算历史会话已经记录的费用。

## Pivot 的配套界面改进

### 询问改为会话底部面板

扩展需要确认、选择或输入时，普通输入区临时收起，询问横向展开显示在会话底部，不再遮罩覆盖聊天记录。自定义扩展交互面板也采用相同布局；消息仍可滚动、选择和复制。

多个询问按顺序叠放：处理当前问题后，恢复前一个未完成的问题及其输入。所有问题结束后，恢复原聊天草稿、附件和输入区；正在上传的文件不会因为收起输入区而被卸载。

底部保留停止生成、停止压缩及错误提示。回复发送失败时保留答案，取消或超时的问题会关闭；切换会话不自动回答原会话问题。通知详情、Models/Tools 等应用对话框保持原样。

### Windows 保存的 MCP 配置可以加载，也可以编辑

某些 Windows 编辑工具会在 UTF-8 文件开头加上 BOM 标记。新版底层可以读取这类 `mcp.json`，减少“文件内容看起来正确，服务器却全部未加载”的情况。

Pivot 的 Tools 编辑与 Packs 操作已同步支持 BOM，并在保存时保留原有 BOM 和换行格式，避免“聊天能使用 MCP，设置页面却提示配置无效”的不一致。

### 导出的中文会话更易阅读

上游 HTML 导出修复了中文标点旁的粗体、斜体显示为原始星号的问题。本次继续保留 Pivot 对深会话树导出的处理。

这一改进针对导出的 HTML。浏览器聊天正文使用另一套 Markdown 渲染，不因这次底层升级自动改变。

## 哪些用户需要留意

**普通聊天用户**：部署并加载本次构建后即可使用，不要求迁移会话、重新登录或重建 Packs。

**使用已退役模型的用户**：升级后若原模型不可用，在 Models 中检查并选择替代模型。自定义模型是否仍受支持，取决于实际 Provider。

**使用 Windows 内置工具的用户**：新版改善 PowerShell 安装目录和 Microsoft Store shell 别名的识别；内置 grep 不再受个人 ripgrep 配置影响。这些变化针对智能体工具，不代表 Pivot 独立终端面板的行为也会改变。

**通过自定义代理使用图片分类的用户**：需要核对服务支持的图片输入格式。不要只凭一次请求成功就认定模型读到了图片；Pivot 已补齐配置传递，仍应按实际服务能力选择模型和格式。

**自行维护扩展的用户**：请求身份、归因头和遥测接口有兼容性变化，依赖这些接口的扩展需要检查。普通用户不需要为此修改 API key 或开启遥测；本轮也不新增遥测页面或自动上报配置。

技术范围与完成记录见 [pi 1.4.0 适配计划](specs/pi-1.4.0-upgrade-plan.md)及 [底部询问面板方案](specs/session-inline-interaction-plan.zh-CN.md)。
