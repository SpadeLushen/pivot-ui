# 会话底部内嵌询问面板实施方案

状态：**已在 pi 1.4.0 适配及第一阶段构建通过后完成代码改造，第二阶段构建通过**。尚未执行行为测试或浏览器验收；本次未控制运行服务。

## 1. 目标与排期

当扩展需要用户确认、选择或输入时，临时收起会话底部的普通输入区域，将原有询问内容横向展开并放在底部，成为会话布局的一部分。处理完所有待答询问后，恢复原输入区域和草稿。

- **保持 `mode: "tui"` 定义不变**；布局改变不影响扩展看到的模式和权限响应语义。
- **先完成 pi 1.4.0 适配**：依赖、codemode、交互请求栈/关闭通知/重连、BOM、classifier compat，以及约定的构建与完成记录；行为验收按届时用户授权范围执行，未覆盖项明确记录。
- 随后再实施本方案，复用适配阶段交付的交互状态，不再建立另一套请求栈。
- SDK 适配阶段 U3 只修复交互生命周期，保留届时的展示形式；本阶段再更换展示容器。发布、版本号及服务控制不属于本方案的自动操作。

技术前置见 [pi 1.4.0 适配计划](pi-1.4.0-upgrade-plan.md)。

## 2. 用户看到的界面

```text
┌──────────── 当前会话 ────────────┐
│ 消息与工具记录                   │
│ 可继续滚动、选择、复制             │
├─────────────────────────────────┤
│ 需要确认 · 标题        待处理 2 项 │
│ 询问说明 / 选项 / 输入内容         │
│                                 │
│ [取消]                   [确认] │
└─────────────────────────────────┘
```

没有询问时，下方仍是原来的聊天输入区。有询问时，输入框、附件按钮、模型等输入工具栏一并隐藏，由当前询问面板占据该位置；不是在输入框上方另堆一个浮层，也不是移到历史消息列表里。

- 面板宽度填满当前会话列的可用宽度，保留左右边距；不沿用原弹窗的 560/920px 宽度上限，也不跨越侧栏或右侧工具面板。
- 取消遮罩、阴影悬浮效果和拖动标题栏；面板与消息区域以分隔线和现有主题色区分。
- 短确认按内容定高；长选项、editor 和 custom 具有内部滚动区。editor/custom 推荐初始约 240–320px，总高度一般不超过可用会话高度的一半，给历史消息保留空间。
- 标题与操作栏不随正文滚走。手机、横屏及软键盘出现时以实际可用高度为准，优先保证输入和提交可见，不恢复为全屏遮罩。

## 3. 交互范围与规则

### 覆盖哪些界面

纳入会话扩展的 `select`、`confirm`、`input`、`editor`，以及通过 `ctx.ui.custom()` 打开的交互面板，包括权限扩展发出的确认询问。custom 一并迁移，避免刚收起普通弹窗又出现另一种遮罩。

通知及其详情、Models/Tools/Packs 配置、全局删除确认、登录等应用对话框不在范围内；仍采用各自原有展示。普通 status/widget 不触发输入区收起。

### 多个询问与结束时机

沿用 1.4.0 适配阶段的请求栈：新询问置顶，处理后恢复上一个未结束询问；只展示一个活动面板，可显示待处理数量，但不增加任意切换栈顺序的操作。后台 custom 重绘不能抢占当前询问。

- 有任一待处理请求时保持普通输入区收起；全部请求结束后才恢复，不在连续询问之间闪现输入框。
- 回答提交中显示进度并防重复操作。失败时保留答案和面板，显示可理解的错误；不能因本地点击就当成服务端已接受。
- 超时、取消、被其他客户端回答及重连恢复，以适配后的权威请求状态为准；已失效的询问不得重新显示。
- 切换会话不自动回答或取消原会话询问；展示状态按会话隔离，返回时与服务端同步。

### 草稿、焦点与安全

普通 ChatInput 保持挂载，仅收起并退出焦点/辅助技术可访问区域；保留文字、附件、上传进度、光标及选择范围，不依赖卸载再从 localStorage 恢复。询问答案与聊天草稿分开保存；询问输入仅按会话/request id 保存在内存，不新增敏感答案持久化。

首个询问在用户编辑普通输入时，将焦点转到询问的合适控件。后续重绘不反复抢焦点；已有聊天文字选择或用户正在看历史时，不强制打断。恢复输入区时，仅在焦点仍属于已关闭询问且会话未切换时恢复原焦点，不抢走用户已移到消息、侧栏或右侧面板的焦点。

- input 用 Enter 提交，editor 用 Ctrl/Cmd+Enter；中文输入法组合期间不触发提交。
- confirm 不让一个迟到的聊天 Enter 自动变成授权；焦点默认不放在危险确认按钮上。
- Escape 只在活动询问内部按原语义取消；custom 的按键仍传给扩展，不将它强行解释为普通确认。显式取消/关闭也保持原有响应语义，不自动批准。
- 点击消息、滚动、复制、切换会话不视为取消。没有 backdrop dismiss、全页焦点陷阱或全局 inert 层；面板采用带标题的非模态 region。
- 输入区隐藏时不能通过快捷键、隐藏菜单、拖入/粘贴附件继续发送。文件链接或扩展写入草稿可更新原草稿，但不能抢焦点或被当成询问答案。
- 保留独立的“停止生成”入口；隐藏输入区不能把唯一的停止按钮一起藏掉。停止 run 与取消单个询问是不同操作，均走原有命令。

错误和重试信息不能因 ChatInput 隐藏而消失；在底部公共状态区或面板操作栏继续呈现。已排队消息不因询问被清空、重发或改变顺序。

## 4. 实现落点与职责

### 当前结构

`components/ChatWindow.tsx` 中的 ExtensionDialog/ExtensionCustomPanel 使用 `SessionDialog`。后者通过 Portal 挂到 document.body，并由 `.session-dialog-layer` 的固定全页布局、背景和 blocker 限制点击；它不是会话底部布局的一部分。`InteractionSurface` 默认也有 dialog/modal 语义和浮层样式。

ChatInput 当前已有保持挂载的安排，拥有草稿、附件上传和 imperative ref；简单地用三元表达式在 ChatInput 与询问之间切换，会丢失这些内存状态。`useChatViewport` 已观察视口尺寸变化并处理跟随底部，可作为面板伸缩的接入点。

### 建议的组件边界

1. **LiveSession / `hooks/useAgentSession.ts`**：继续独占请求栈、会话作用域、响应/关闭、提交状态与重连。不操作 DOM，不因内嵌展示增加平行 EventSource 或请求队列。
2. **`ChatWindow.tsx`**：在现有底部区域组合稳定挂载的 ChatInput 与 `SessionInteractionDock`（拟新增）。有活动请求时隐藏普通 composer，显示 dock；消息视口使用 `flex: 1; min-height: 0`，dock 参与正常文档流并限制最大高度，不使用 fixed/absolute 覆盖记录。
3. **`SessionInteractionDock.tsx`（拟新增）**：只负责布局、标题、待处理计数、独立运行控制及活动请求展示。拆出原 ExtensionDialog 的表单内容与 custom ANSI 内容，复用原选项/键盘编码/响应回调，避免复制第二套协议处理。
4. **`ChatInput.tsx`**：增加明确的 suspended 状态，控制隐藏、关闭菜单、暂停输入交互/焦点副作用，覆盖 imperative methods 的 focus 和发送入口；不拿 isStreaming 伪装输入锁，也不阻止已有上传完成或安全写入草稿。保留当前组件位置/key，恢复后重新计算 textarea 高度。
5. **`components/useChatViewport.ts`**：保留“跟随底部者继续跟随，浏览历史者不被拖走”的规则；仅在真实布局变化需要时补锚定。尺寸/滚动逻辑留在 viewport hook，不放进 LiveSession。面板切换不视作新 prompt，不重置分页、文本选择或 minimap。
6. **`app/globals.css`、`lib/i18n/{zh,en}.ts`**：增加会话范围的 dock 样式和配对文案，使用现有主题变量；清理本功能对 modal/拖拽样式的依赖，不修改全局 `.modal-surface` 来强行扁平化所有对话框。

`SessionDialog` 仍被通知详情使用，不能直接改造成底部容器或整体删除。`InteractionHeader/InteractionChoice` 可复用内容与按钮样式，但 dock 不应继承拖动手柄、全局遮罩、modal aria 或浮层宽度限制。

### 布局与已有行为的衔接

- 使用当前会话列尺寸计算，不用整个 window 高度代替聊天可用高度；右侧面板展开、浏览器缩放和手机软键盘均须重新布局。短过渡只用于高度/透明度，遵循 reduced-motion，不延迟交互可用性。
- 即使空会话通过扩展命令发起询问，dock 也在底部，而非欢迎页中心。不要为此让 ChatInput 更换父节点或 key。
- custom 继续采用现有终端行宽与 ANSI 渲染，横向溢出在自身内容区滚动；“面板变宽”不自动意味着服务器重新计算了终端列数。本阶段不另造终端协议或默认动态重建 custom 组件。
- 收起普通输入区只影响当前客户端的 composer，不更改 SDK 的 steer/follow-up 接收契约，也不全局禁止其他客户端发送。
- 不新增手动拖动/缩放、返回悬浮模式或折叠后继续聊天的开关；先完成统一的底部替换体验。

## 5. 实施与完成条件

原定实施顺序如下，代码与构建已按序完成；实际交付见第六节：

1. **适配完成后重新读取实际代码**：以 U3 最终请求栈/关闭/同步契约为输入，不按本次静态快照重复实现。
2. **分离表单内容与展示壳**：保留通知详情等现有对话框，只将扩展询问/custom 接入底部 dock。
3. **连接 composer suspension**：保持草稿/上传/ref，补齐菜单、焦点、停止按钮、错误提示和误发送防护。
4. **完成响应式与滚动衔接**：普通/空会话、长内容、面板切换、手机软键盘、主题和无障碍处理。
5. **代码完成后在当前工作区执行 `npm run build`**，使用命令自带的编译和打包，不另建构建目录、不额外打包或重启服务。

行为验收目标如下；编写/运行测试及浏览器交互检查须取得相应明确授权，本次未执行：

- **布局**：五类扩展交互均出现在会话底部，横向填充当前列，无 Portal/全页遮罩/blocker；长说明、选项、表单和 custom 的操作栏始终可达。其他应用对话框和通知详情保持原样。
- **草稿**：询问前输入的文字、附件、正在上传的文件、光标和选区在恢复后仍在；隐藏时菜单关闭，Enter、快捷键、拖拽/粘贴不能误发送；草稿写入不抢焦点。
- **生命周期**：多个询问按栈恢复、隐藏 custom 更新不抢占；超时/abort/提交失败/双击/其他客户端回答/断线重连/切换会话不丢请求、不复活失效面板、不交叉响应。
- **权限**：confirm 的默认选择、取消及 custom 按键保持原语义；输入法候选确认不会授权；停止 run 仍可操作，不以 UI 收起绕开工具权限。
- **视口**：原先在底部时随 dock 高度调整保持末尾可见；看历史或选中内容时不被强拉到底；分页/minimap 不复位，选择复制正常。
- **适配屏幕**：桌面宽/窄会话列、展开右侧面板、手机竖/横屏和软键盘下不溢出，不盖住提交；浅/深/护眼主题及键盘/屏幕阅读器导航正确。
