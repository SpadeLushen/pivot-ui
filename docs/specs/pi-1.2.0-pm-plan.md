# Pivot UI 适配 pi 1.2.0：产品需求与交付计划

**面向对象**：PM、产品负责人及验收参与者。  
**当前状态**：D1／D2 代码实施及本地自动化验证已完成，修正后构建通过；用户已授权提交改动并单独提升版本至 2.1.0。真实账户、完整产品验收与上线仍未完成，不将提交等同发布。实施状态见第九节，测试结果见第十节。  
**参考**：[官方更新说明](https://pi.dev/changelog) · [研发适配计划](pi-1.2.0-upgrade-plan.md)。技术实现和风险取证以研发计划为准。

## 1. 为什么做这次更新

本次更新包含必要兼容和一项新能力接入，不把现有功能重新包装成升级收益。计划分为三类：

| 类别 | 本次含义 | 是否对应开发工作 |
|---|---|---|
| 明确交付 | 插件输入组件兼容、OpenRouter 个性化目录 | 已发现接入缺口，需要开发 |
| 升级行为适配 | 准备／取消、插件任务规则、配置与 MCP 行为变化 | 先复核差异，发现不兼容才修改 |
| 不可退化底线 | 历史会话、Fork、导出、既有设置与费用记录 | 回归验收，不预设新增开发 |

上游已提供部分稳定性改进，但不等于 Pivot 自动完成接入，也不等于已在真实账户和第三方服务上验证。

## 2. 用户与场景

| 用户／场景 | 用户诉求 |
|---|---|
| 日常聊天、恢复历史会话 | 升级后继续工作，无需重新配置或迁移历史 |
| 使用插件交互面板 | 输入、显示和复制内容正常，不出现奇怪字符或缺字 |
| 执行长任务或复杂工具流程 | 准备阶段就能感知任务状态，取消后不误报成功 |
| 管理工作区和工具权限 | 已禁用或隐藏的工具始终不可用，插件发起任务也遵守规则 |
| 使用 OpenRouter 或切换密钥／地区 | 模型列表和额度相关信息及时更新，断网时知道信息可能过期 |
| 使用 MCP 外部服务 | 资源列表缓慢不拖住工具可用性，取消和登录安全边界可靠 |

## 3. 明确交付、行为适配与验收底线

### 3.1 明确要交付：有具体适配工作

**D1：插件输入组件兼容（P0，原 R2）**

- **为什么做**：插件输入面板现有版本已可用，但新版 pi 改变了光标内容的表示方式，Pivot 现有显示路径不能正确处理。不是新增面板功能，而是避免升级造成异常字符或缺字。
- **本次工作**：适配显示、布局和复制对这些新内容的处理；不重设计插件交互。
- **交付结果**：中文、emoji、光标字符和窄窗口显示正常，复制正文不夹带隐藏标记。

**D2：OpenRouter 个性化目录接入（P1，原 R5，建议同批交付）**

- **为什么做**：新版可提供当前密钥／地区对应的聊天模型信息，但 Pivot 现有刷新流程未完整接入；仅升级版本不能获得完整能力。
- **本次工作**：接入模型选择／明确刷新及密钥、地区变化后的更新，提供等待上限和离线／失败反馈，避免旧请求覆盖新连接信息。
- **交付结果**：支持时展示当前连接对应的聊天模型、上下文容量、输出限制和价格；历史浏览、登录状态查看不被目录联网拖慢。
- **能力边界**：不筛选图片／分类模型。部分代理不支持个性化目录，查询被拒绝时上游也可能回退到通用列表；列表不等于权限验证。缓存可能过期，不能冒充已验证最新。

### 3.2 升级行为适配：先复核，发现问题才修改（P0）

**A1：准备阶段与取消（原 R3）**

新版把任务准备阶段也算作忙碌，并调整期间取消和排队的行为。核对已有发送、状态、取消及断线恢复是否仍正确，不预设新增一套任务控制或阶段界面。忙碌不能误当输入已接受，取消不能误报成功；取消不保证立即打断准备工作，也不撤销已有外部副作用。

**A2：插件任务规则与 MCP（原 R4）**

新版让插件发起任务经过统一准备流程，并改变外部工具的连接等待、结果处理和取消后的行为。核对现有工作区规则是否继续有效、禁用工具是否不可间接调用、慢资源列表是否不拖住工具、取消后是否不补发请求。主要承接上游变化，不预设重做权限系统；发现 Pivot 不兼容才修复。

**A3：新版配置要求（从原 R1 分离）**

新版对部分模型参数和自定义主题的合法性要求发生变化。复核现有加载／错误反馈，必要时补兼容；不预设开发新配置编辑器。无效内容应有反馈，保留原文件，不清空或静默修正；登录安全校验不能为兼容而降低，已返回的新凭据仍需安全保存。

### 3.3 不可退化底线：已有能力，不算新增收益

**G1：用户资产与既有操作（原 R1 的主要内容）**

历史会话查看／继续／分支、Fork、导出、登录信息、模型设置、工具开关、工作区信任和历史费用均已存在。本次没有明确增强这些功能的计划，只确认升级不破坏它们。

验收底线：历史与设置不被擅自修改，Fork 不影响原会话，用户调整设置不改变在途任务的权限配置，历史费用不重算。发现回归时修复，不单独包装成新功能。

**交付说明**：若 D2 延期，必须明确“完成 1.2.0 兼容，未完整接入 OpenRouter 个性化目录”，不能宣传完整支持。

## 4. 可承接的稳定性收益

以下是本轮预期获得、但仍需按授权范围验收的收益，不要求逐项增加新界面：

- 减少部分长时间模型生成被提前中断的情况。
- 对特定临时服务错误进行重试，减少任务无必要地终止。
- 降低长会话压缩或分支摘要失败的风险，保留原始历史内容。
- 改善批量工具调用的输出性能和工具说明，让模型更容易正确使用工具。
- 承接登录、外部工具调用取消和部分 Windows 凭据读写的修复。

不承诺所有服务错误均可恢复，也不将这些改进包装为已测量的成功率或性能提升。

## 5. 范围控制与交付节奏

**本轮不做**：新模型产品界面、插件中心重设计、远程执行平台、云端部署、任务回放体系，以及浏览器聊天对终端专属功能的全面复刻。也不自动合并账户、迁移凭据、重算历史费用。

建议按四个里程碑推进，时间由研发评估后确认：

1. **兼容交付与差异复核**：采用 pi 1.2.0，完成 D1；对 A1–A3 记录“无需修改”或具体修复项，不将复核直接计为新增功能开发。
2. **目录能力**：完成 D2 的刷新、连接变化和离线／失败反馈。
3. **验收**：分别确认明确交付、行为适配和 G1 回归底线；按已获授权的范围执行，真实账户、第三方服务和发布包运行单独记录证据。
4. **发布决策**：确认范围、遗留风险和部署安排后再发布。开发完成不自动意味着服务已更新。

本文不设未经评估的工期或量化收益。工作量分开记录：明确开发、差异复核／按需修复、回归验收。若拆分交付，须分别记录兼容完成与 D2 新能力完成。

## 6. 产品验收标准

以下为完整验收标准；已完成的本地自动化覆盖见第十节，不代表整份矩阵已验收。既有验收及已决定跳过的项目不因此自动重开。

| 类别／项目 | 关键验收场景 | 通过标准 |
|---|---|---|
| 明确交付 D1 | 插件输入中文／emoji、移动光标、改变宽度、复制正文 | 新版输入组件无异常标记、缺字和复制污染 |
| 明确交付 D2 | 受限密钥、换密钥／地区、刷新失败、断网、代理回退 | 支持时目录匹配连接；过期／失败不冒充最新，回退不误称权限验证成功 |
| 行为适配 A1 | 长准备、重复发送、失败、取消、刷新／断线恢复 | 状态与实际任务一致，取消不误报成功，无长期忙碌；明确复核是否需要修改 |
| 行为适配 A2 | 插件发起任务、间接调用禁用工具、慢资源列表、登录刷新时取消 | 规则不被绕过，资源读取不拖住工具，取消请求不补发；明确修复或上游承接 |
| 行为适配 A3 | 新版不接受的模型参数／主题、加载及保存配置 | 有错误反馈，保留原内容，不静默清空或修正；不预设重做编辑器 |
| 回归底线 G1 | 旧会话、Fork、导出、登录／设置、历史费用 | 已有操作可继续，资产不被擅自修改；通过仅表示未退化，不算新增收益 |
| 上游稳定性收益 | 受影响的长生成、重试、长会话摘要和批量工具流程 | 有对应证据才宣称收益，不以开发或构建成功替代运行验收 |

验收记录应区分“已实现”“已验证”“未覆盖／跳过”。真实账户或第三方服务不可用时，记录具体边界，由产品负责人决定延期该能力还是接受带限制交付，不直接勾选通过。

## 7. 主要风险与 PM 决策点

| 风险 | 产品处理原则 |
|---|---|
| 第三方插件不适应新版 | 区分 Pivot 兼容问题与插件自身问题；不给“所有插件无缝兼容”的承诺 |
| 部分手写主题／配置不再被接受 | 提供错误说明，保留原文件，不自动清空或迁移 |
| 目录缓存来自旧密钥或旧地区 | 提示信息可能过期并刷新；不以列表作为安全授权依据 |
| 外部登录因更严格校验失败 | 安全优先，不绕过校验；明确为未完成授权而非系统成功 |
| 当前服务尚未加载升级版本 | 发布与服务更新单独安排，避免“已开发”等同“已上线” |

需要确认的交付取舍：

- **建议范围**：D1 必要兼容与 D2 OpenRouter 同批交付，A1–A3 完成差异复核及必要修复；G1 作为回归底线，不作为新增需求。若延期 D2，明确缩小版本承诺。
- **验收范围**：确认可用的真实账户／外部服务，以及哪些边界允许暂未覆盖。
- **上线安排**：另行确认服务更新窗口和发布授权，不因本文生成而执行。

**范围说明**：初次规划未充分说明现有手动刷新和 OAuth 登录后刷新。本轮复用这些能力，补齐聊天选择、API-key／配置变更及刷新协调，不是从零重做模型目录。

实施阶段工作区构建及自带打包通过，后续测试发现问题的修正后构建也通过；保留 16 条文件追踪警告。详细证据见研发计划第七、八节。上述测试和构建基于 Pivot 2.0.2；用户随后授权升至 2.1.0 并提交，版本变更为本次最后一个独立提交。不自动推送、重启现有服务或发布；对外公告仍需等待相应验收和上线决定。

## 10. 用户授权后的自动化验证

- **专项**：71 项全部通过，包含 5 项新增本地 Chrome 用例和真实 SDK 适配验证。
- **完整回归**：106 个测试文件、641 项；637 通过、4 跳过、0 失败。
- **跳过项**：Windows 上的 3 项 PTY；未配置生产测试目录的页面冒烟。它们不算已验证。
- **发现并修复**：光标保护同时留下普通尾空格，已改为只保留光标字符；测试服务补 UTF-8 声明；旧 Fork 断言按现有源保留契约更新，增加源会话和文件不变检查。没有为通过测试改变 Fork 产品契约。
- **隔离与边界**：使用临时配置、本地服务和模拟 Provider 响应，不请求真实账户。浏览器验证为受控 fixture；文本选取不等于系统剪贴板，完整应用、真实账户与安装后运行仍待验收。

测试后已再次构建通过，没有把第一次失败、权限阻止或跳过项计入通过数。具体命令、日志、修正与剩余范围见[研发计划测试记录](pi-1.2.0-upgrade-plan.md#8-用户授权后的测试与修正)。
