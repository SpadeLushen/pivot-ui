## “完成”是什么意思？

- **开发完成**：代码已实现；“构建通过”表示编译和生成应用成功，不表示所有操作都已验证。
- **验证完成**：实际操作或自动化检查已通过。只通过一部分时明确写出范围；跳过不算通过。
- **交付完成**：最终验证及获授权的安装、部署／发布已完成。

当前 D 阶段**尚未交付完成**。这些开发记录不代表已经发布或更新运行中的服务。本计划也不自动授权测试、部署、重启、提交或发布。

### 几个词的日常含义

- **Provider**：模型服务商或服务连接，例如一组地址和登录／密钥设置。
- **Classifier**：分类模型，按指定问题判断文本或图片，不是聊天模型。
- **虚拟模型／路由模型**：你选择的是一个“自动选模型”的入口，实际回答可能来自不同模型。
- **采样参数**：影响回答生成方式的参数；本阶段仍由你在 JSON 配置文件中手改。
- **扩展／Built-in**：扩展给 pi 增加能力；Built-in 指其内置扩展，不是另装的插件包。

## 各批次：做什么、做到哪里、还需什么

### D1：发送与排队状态准确

- **解决什么问题？** 输入可能被命令处理、加入队列或真正启动模型；界面不应一律显示模型正在回答，也不应留下实际没有发送的消息。
- **使用上有什么变化？** 区分“发送中”和“运行中”；失败时保留输入并显示错误，排队状态跟随真实处理结果。
- **当前进度？** 开发完成、构建通过；普通发送已获你人工确认。
- **还有什么未确认？** 命令处理、排队、取消、断线、快速切会话，以及完成提示音等复杂情况。你已要求安排自动化，尚未执行。
- **需要你做什么？** 不要求你逐一手动复现这些复杂情况。自动化后续仍需实际执行并记录结果；这里只保留安排，不把它写成已通过。

### D2：不同用途的模型被正确识别

- **解决什么问题？** 分类和图片模型不应被当作聊天模型；只提供分类服务的 Provider 也应能被识别和配置认证。
- **使用上有什么变化？** Models 中按用途查看模型；聊天选择器只列聊天模型，测试入口按类型处理。当前分类测试需要结构化 JSON 输入；图片模型不会被 Test 按钮直接调用生成图片。
- **当前进度？** 开发完成、构建通过。服务商／目录和现有聊天模型测试人工验收通过。
- **还有什么未确认？** 非聊天模型的隔离和真实调用、配置字段保留、部分取消／超时等情况。原验收第 2、4、5 项跳过，不算通过。
- **需要你做什么？** 后续可明确要求自动化验证。真实分类调用另需可用的服务和凭据；不是仅看到模型列表就能确认可调用。

### D2b：在设置中添加分类和图片模型

- **解决什么问题？** D2 能识别不同类型，但还需要让你在自定义 Provider 中创建它们、保存并供后续加载。
- **使用上有什么变化？** 自定义模型详情可选择聊天、分类或图片类型，并填写对应连接信息；同一服务商的同名模型可按不同类型区分。
- **当前进度？** 开发完成、构建通过；界面已确认。
- **还有什么未确认？** 实际调用因缺少 API 资源暂未验收；重新打开、进程重建后恢复、删除／改名及保存失败等边界仍待验证。扩展自定义 API 的自动发现／下拉选择暂不实现。
- **需要你做什么？** 有可用的分类／图片服务后再做真实调用验证；图片生成界面属于 D7，当前 Test 不生成图片。保存／恢复等本地检查也可在明确要求后安排。

### D3：看清“选择的模型”和“实际回答的模型”

- **解决什么问题？** 选择自动路由入口后，不应因为它用过某个模型回答，刷新时就悄悄把你的选择改成那个模型。
- **使用上有什么变化？** 分开显示你选择的入口与最近一次成功回答所用的模型；统计增加按实际模型归属的费用分组。无法拆分的费用会说明未归属，不猜测。
- **当前进度？** 开发完成、构建通过。
- **还有什么未确认？** 连续调用不同模型、刷新、恢复、切换会话分支、复制出新会话，以及失败／取消时显示与费用是否一致。
- **需要你做什么？** 验收需要可用的路由扩展和模型；可另行安排自动化及真实使用检查。没有路由入口时，不要求你仅靠普通聊天完成这些验收。

### D4：手写参数不被其他设置修改误删

- **解决什么问题？** 在 JSON 中手动设置采样参数后，用 Models 修改名称、费用等其他设置，不应把原参数删掉或改成默认值。
- **使用上有什么变化？** 不新增采样控件，仍手改 JSON。打开 Provider 详情不再自动补写 API 默认值。
- **当前进度？** 保留链路的静态核对和最小修改完成，构建通过。“静态核对”是阅读代码确认处理方式，不是实际操作验证。
- **还有什么未确认？** 实际完成一次“修改无关设置并保存”，确认普通参数、按思考档位设置的参数和服务商覆盖参数仍保持原值，包括 0、false、null 和自定义字段。
- **需要你做什么？** 手改 JSON 后重新打开 Models，再修改其他设置并保存；后续可明确要求安排这一验证。不承诺自动合并已打开表单期间外部文件的新改动。

### D5：扩展显示兼容与内置扩展管理

已按 D5a → D5b 的顺序开发，两项用途不同：

- **解决什么问题？** D5a 补齐插件调用的颜色／样式接口，减少插件兼容问题；D5b 帮你知道内置扩展到底有没有加载、是否被第三方插件替代，以及为什么出错。
- **使用上有什么变化？** D5a 是幕后修补，没有新增主题编辑器，也不把终端界面完整搬到网页。Plugins 采用 **Installed**／**Built-in** 两个标签页，默认打开 Installed（已安装的插件包）；Installed 内容区与 Tools 使用相同留白；Built-in 采用左侧扩展列表、右侧详情与开关，列出 mcp、codemode、tool-search，底部选择保存到全局或工作区，开关修改立即保存。开关表示设置，旁边另列所选会话最近加载的状态及是否等待空闲重载。
- **当前进度？** D5a、D5b 均开发完成，当前工作区构建通过；尚未行为验收。
- **还有什么未确认？** 插件使用主题接口、多会话互不影响，以及内置开关、第三方替代、加载错误、工作区信任、运行中延后生效和失败后重试，均待实际验证。没有选中的运行会话时，加载状态显示未知，不表示已生效。
- **需要你做什么？** 可打开 Plugins → Built-in 检查界面；工作区开关需明确信任该工作区，全局编辑不要求信任。后续可明确要求安排行为验证；开关只控制对应内置扩展，不会自动禁用替代它的第三方插件。

### D6：更容易使用的分类界面

- **解决什么问题？** 当前分类测试需要手写结构化输入；希望用更直观的界面填写输入、分类问题并查看结果。
- **使用上有什么变化？** 建议首版放在 Models 详情／测试中，支持文本或图片输入、执行／取消及结果展示；有记录时显示耗时和费用。
- **当前进度？** 未开发，以上是建议，不是已经确定的产品范围。
- **还有什么未确认？** 首版输入形式及不同分类模型的要求。独立测试费用不混入聊天会话费用，分类结果不能用于自动授予工具权限。
- **需要你做什么？** 确认是否采用“先在 Models 内做最小界面”的方案；真实验收另需可用分类服务。

### D7：右侧面板图片生成

- **解决什么问题？** 想直接在 Pivot 中输入生成需求、查看并保存图片，而不只是显示聊天工具返回的图片。
- **使用上有什么变化？** 建议增加右侧图片工具，首版做单次生成、取消、多图结果，以及明确的保存／下载动作。
- **当前进度？** 未开发，首版范围待确认。
- **还有什么未确认？** 保存位置、命名、覆盖规则、清理方式及未保存图片保留多久。首轮不做画布、批量任务或作品库；生成可能收费，取消不保证服务商不计费。
- **需要你做什么？** 确认首版功能和图片保存规则；真实验收需可用的图片服务。不会在查看目录或点击普通 Test 时悄悄生成图片。

### D8：模型响应过程诊断

- **解决什么问题？** 排查模型请求为什么慢、卡住或出错，避免只凭最终聊天结果猜测。
- **使用上有什么变化？** 建议提供默认关闭、手动开启的诊断能力，只显示必要的事件类型、时间和计数，不直接展示原始请求／响应内容。
- **当前进度？** 未开发，优先级最后；先评估已有调试扩展是否够用。
- **还有什么未确认？** 是否需要独立面板。必须限制数据量、关闭后清理、不默认保存或导出，且不能泄露密钥、完整文本或图片数据。
- **需要你做什么？** 确认是否确实需要独立诊断界面；更详细的内容记录／报告要另行设计隐私边界。

## 接下来怎么安排？

1. **开发已到 D5**，主题兼容与 Built-in 管理已按顺序实施。
2. **补使用验证：D1–D5**，保留已通过项目，只补未确认部分；D1 自动化已安排，其余测试执行需明确要求。
3. **确认新增界面：D6–D8**，尚未决定或暂缓都不算完成；不阻塞 D1–D5。
4. **最后交付**：统一安排最终验证和获授权的安装／部署，不按每个开发批次单独发布。

另有一项评估：是否在聊天界面增加“显示隐藏消息”开关。目前未纳入首轮开发。已有导出 HTML 的开关不等于聊天界面已经支持。

## 最终交付前仍需确认什么？

这些不是 D5 的剩余开发，也不能用一次构建通过替代：

- 真实模型账户登录、刷新和取消是否正常，原凭据是否保留。
- 真实分类／图片服务的调用、费用，以及外部 MCP 工具服务的登录、调用和断连。
- 历史／长会话、完整输出、断线恢复、完成提示音和 HTML 导出。
- Windows 终端与文件权限；真实工作区中的文件、Git、终端和 Packs 能力。
- npm／pnpm 安装后的应用是否能启动；部署产物与实际运行的进程是否匹配。

这些验证、安装和服务控制需按原授权边界另行安排，不能因为本次整理文档就开始执行。
